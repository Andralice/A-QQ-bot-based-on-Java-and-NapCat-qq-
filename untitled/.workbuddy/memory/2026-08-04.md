# 2026-08-04 工作日志

## 调研：AstrBot 项目（GitHub: AstrBotDevs/AstrBot）
- 用户询问 GitHub 上的 astrbot 项目是什么、有哪些功能。
- 结论：AstrBot 是一个开源（AGPL-3.0）的全能型 AI Agent 聊天机器人平台 / 开发框架，用 Python 3.12 编写。可接入 QQ（OneBot v11）、企业微信、飞书、钉钉、微信公众号、Telegram、Discord、Slack、LINE、KOOK 等十余种 IM 平台。
- 核心能力：多平台 LLM 对话（支持 OpenAI/DeepSeek/Gemini/智谱/月之暗面/本地 Ollama 等）、多模态、Agent、MCP、Skills、内置知识库（混合检索 BM25+向量）、人设/情感陪伴、Agent 沙箱（隔离执行代码/Shell）、WebUI+ChatUI、1000+ 社区插件、定时任务（Cron）。
- 部署方式：uv 一键、Docker/Compose、桌面端、雨云/宝塔/1Panel/CasaOS、AUR 等。
- 关联：当前工作区是基于 Java + NapCat 的 QQ 机器人。AstrBot 是更"全栈"的 Python 替代/对比方案，用户可能在进行技术选型调研。

## 用户澄清（重要）

- 后续若给优化建议，应聚焦"在 Java+NapCat 上如何落地"，而非迁移方案。

## 代码调研结论（已读核心代码）
- 项目代号"糖果熊"，架构成熟度**已超 AstrBot 基础功能**：已有分段发送(`sendSplitGroupReplies`+`splitIntoShortMessages` 支持 XML/空行/代码块保护)、三层限流(群/用户冷却+`SpamDetector`)、群/私聊白名单、Tool 工具系统(等价 MCP)、三层记忆(LongTermMemory/Belief/ConversationState)、知识库、主动消息(Schedule/SendGroup)、自进化(evo/)、审计模型、CP追踪、情绪系统、WebDashboard。
- **真正空白/薄弱点（可从 AstrBot 借鉴的增量）**：
  1. **无"正在输入"(typing) 状态** —— grep 确认全代码无 `typing`/`set_typing_status`。AstrBot 真实感核心细节，低成本高感知。落点：`Main` 加 `sendTyping(groupId,bool)` 便捷方法 + `AIHandler` 在 `generate()` 前发 true、发完发 false。需验证 NapCat 是否透传 `set_typing_status`（QQ 官方机器人有，OneBot v11 不一定）。
  2. **分段节奏**：当前 `Thread.sleep` 阻塞 executor，且 typing 只在生成后才 sleep。优化为"生成前就亮 typing + 首段极短延迟"。
  3. **主动插话决策层(Proactive)弱**：主动消息均工具显式触发，缺"bot 自主判断何时主动说话"。可用已有 `ScheduleRecurringTask`+`moodService` 做 cron 唤醒 LLM 决策（进阶，符合"Java 不替 LLM 判断"哲学）。
